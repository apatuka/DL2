## API final

```cpp
namespace dl2::simulation {
enum class TaskForceDissolutionAction : uint8_t {
    ArmyReleased, ArmyTransferred, ChildReparented, ParentLinkCleared };
struct TaskForceDissolutionStep {
    TaskForceDissolutionAction action;
    int slot;                            // ranura 0..15 o palabra de hijo 0..14
    uint32_t armyId;                     // acciones de unidad
    int16_t armyJobBefore, armyJobAfter; // Army.job alrededor de la acción
    TaskForceEditReport removal, insertion; // ArmyTransferred: informes de las APIs públicas
    int jobIndex;                        // hijo (ChildReparented) o padre (ParentLinkCleared), 0-based
    int32_t linkBefore, linkAfter;       // child.parentJob, o palabra del padre limpiada
    int rootSlot;                        // palabra de job0 escrita; -1 si estaba llena
};
struct TaskForceDissolutionReport {
    int player, jobIndex, parentJobIndex; // padre 0-based leído ANTES de cualquier efecto; -1 sin padre
    std::vector<TaskForceDissolutionStep> steps; // orden real; el borrado final de 0xc4 bytes es implícito
};
bool dissolveTaskForce(const save::Document& source, int player, int jobIndex,
                       save::Document& destination, TaskForceDissolutionReport& report,
                       save::Error& error);
}
```

Coincide con la propuesta anotada antes de programar; no se ha ampliado ninguna
interfaz compartida. `player` es el slot físico del array de jobs, `jobIndex` es 0-based.

## Semántica portada y decisiones de representación

1. **Ranuras**: se recorren las 16 `armyIds` en orden, leyéndolas en vivo en cada iteración
   (`mov ebx,[esi]` en `0040bef9`). `Job.armies` histórico nunca se lee como puntero:
   `armyIds` es la referencia resuelta autoritativa, como en `ai_session`.
2. **Sin padre** (o dominio ≠ 1): sólo se escribe `Army.job = 0` (`0040bf2a`); la ranura conserva
   el ID hasta el `memset` final. Esto es observable con autoparentesco (ver pruebas).
3. **Con padre**: `MOVSX` del tipo y `MOVSX` del byte canónico de dominio, `DEC/JNE`: sólo dominio
   **canónico** 1. Nunca se consulta `Army.unitClass` guardado. Consecuencias reales de la tabla:
   Sea Mine (38) tiene dominio 1 y se transfiere; AAV (27, dominio 6), aire (3) y mar (2) se
   liberan. El tipo 12 (Sea Transport) es dominio 2: se libera **sin** recursión a su carga; la
   recursión tipo 12 de `0040adf4` es inalcanzable desde `0040beb4` con datos canónicos.
4. **Transferencia** = `removeArmyFromTaskForce` y después `addArmyToTaskForce` públicos, en ese
   orden (`0040bf19` → `0040bf23`). Si el segundo devuelve `Full` o `AlreadyPresent`, la unidad
   queda desprendida (`Army.job = 0`) y no incorporada; el informe conserva ambos resultados.
   `removal` sigue `Army.job` (puede retirar de otro job que también la lista).
5. **Padre** resuelto una sola vez al inicio con `Job.owner`/`parentJob` (`0040bec5`). Importa
   cuando un enlace hijo apunta al propio job: el reparentado reescribe su `parentJob`, pero
   `0040afa4` usa el padre original.
6. **`0040b000`**: busca la primera palabra libre de job0 del propietario; el índice escrito se
   deriva del `owner` del **hijo** (`0040b01c`), el del padre del `owner` de job0 (`0040b048`), y
   `child.parentJob` se escribe **siempre**, aunque la lista esté llena (`0040b065`). Disolver
   job0 hace que el propio bucle lea palabras que acaba de rellenar (15 pasos, probado).
7. **`0040afa4`**: compara direcciones de 32 bits usando el `owner` del **padre**; como
   `0x2648 == 50*0xc4` y `0xc4 == 4*49`, equivale exactamente a igualdad de índice lineal módulo
   2^30, sin punteros ni direcciones del ejecutable. Limpia todas las coincidencias (sin `break`).
8. **`memset(job,0,0xc4)`**: `owner` queda a 0, no se restaura.
9. **Transacción**: candidata privada; cada llamada pública puede reemplazar su almacenamiento,
   por lo que las referencias C++ se re-adquieren tras cada una. Éxito publica la candidata
   (también si no hubo cambios) y limpia `error`; fallo conserva fuente, destino e informe,
   incluido `source == destination`. Sin RNG, `gs`, `gg`, mensajes, IA ni borrado de entidades.
   Semántica offline/anfitrión heredada de las APIs públicas (la guarda de red de `0040adf4`
   no se modela; el juego individual es su dominio).

## Dominio admitido y rechazos explícitos

Admitido: `player` 0..6, `jobIndex` 0..49 (incluido job0: `00403350` recorre los 50). Un registro
sin padre, sin `armyIds` y sin palabras hijo se pone a cero sea cual sea su `owner` (reciclado
real de jobs libres por `0040ad88`; las palabras `Job.armies` históricas no cuentan como
referencias). También se admiten autoenlaces, enlaces repetidos y palabras arbitrarias del padre.

Rechazado con error y rollback completo (también tardío, tras efectos previos en la candidata):

| Caso | Motivo |
| --- | --- |
| Documento inválido o mapa reducido | contrato de partida guardada |
| `player`/`jobIndex` fuera de array | índice |
| Job con referencias y `Job.owner != player` | el original direcciona otro array |
| `parentJob` fuera de 1..50 | dirección fuera del array propietario |
| ID no resuelto o `Army.owner != player` en una ranura visitada | criterio de `0040aebc`: limpieza diferida = CX-01; no se borra ni desvincula |
| Errores de las APIs públicas (`Army.job` fuera de 1..50 o sin coincidencia; padre con `owner` ajeno y hueco libre) | contrato existente de `ai_session` |
| Palabra hijo fuera de 1..50 | el original leería/escribiría fuera del array |
| `0040b000` escribiría un índice cruzado (`owner` del hijo con job0 libre, o `owner` de job0) | enlace no mantenible en el array propietario |
| Tipo fuera de tabla canónica | defensivo; inalcanzable con documentos validados |

  `parentTransfers`, `parentAddressArithmetic`, `selfLinks`, `zeroJob` en cada éxito.

  lista llena, orden exacto de pasos y documento completo comparado con un oráculo derivado

  éxito y conservado/reemplazado en fallo, informe centinela intacto, globales/RNG intactos —
